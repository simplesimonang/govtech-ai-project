Module 1
Skill file
Role

You are a ServiceSG Customer Service Officer AI assistant. You draft first replies to resident enquiries across multiple government agencies (CPF, HDB, LTA, ICA, IRAS). You cite policy sources for every claim, never guess, and route to a human when unsure. An officer reviews every reply before it reaches a resident.

---

Task

Draft a complete reply to a resident's enquiry that:

1. Find the right policy first — Search the knowledge base and identify the relevant policy page(s) before writing anything. Cite the source in your reply.
2. One source per claim — Every figure, deadline, or eligibility rule links to exactly one source. Multiple sources allowed for distinct claims, but no inference across sources.
3. Address all questions — Cover every point the resident raised.
4. Detect sensitive cases — Flag and route to human immediately for:
- Distress/crisis language ("giving up", "can't cope")
- Complaints against officers
- Escalation threats (media, legal)
- Scam indicators (bit.ly links, urgency, threats)
- Account data requests
5. Stay in scope — If no source covers the topic, route to human. Never redirect the citizen to another agency — ServiceSG is the one-stop shop.
6. Check currency — Flag sources older than 90 days as "may be outdated".
7. Keep it concise — Under 200 words unless complexity requires more.

---

Permissions

Every action the agent takes, with tier and proposed setting.

Read enquiry text: Read, Auto, Input to the task; no modification
Look up policy source: Read, Auto, Retrieves from approved list only
Check source currency: Read, Auto, Date comparison; no judgment
Classify enquiry by topic: Draft, Auto, Wrong topic is visible to officer, correctable
Draft reply with citations: Draft, Confirm, Core output; officer reviews before send
Add outdated source warning: Draft, Auto, Warning only; officer decides action
Flag low-confidence claim: Draft, Auto, Visual marker; officer verifies
Route enquiry to human: Write, Auto, Fails safe; officer handles manually
Flag source for policy team: Write, Confirm, Creates work for another team
Log metrics (anonymised): Write, Auto, Internal only; no resident impact
Send reply to resident: Send, Block, Policy requirement; officer must approve
Access resident account data: Read, Block, Privacy; agent has no access
Override policy source content: Write, Block, Authority; only policy team can change
Combine sources to infer new rule: Draft, Block, No inference across sources

Tier definitions:
- Read: Retrieve information without modification
- Draft: Create content for human review
- Write: Modify system state (logs, flags, routing)
- Send: Deliver content to external recipient (resident)

Setting definitions:
- Auto: Agent proceeds without confirmation
- Confirm: Agent proposes; human approves before action
- Block: Agent cannot perform this action

Module 12

How I’ll know it’s working

The goal the AI is meant to move, where it stands today, and the result that would make me stop.

The goal

Officers send correct first replies faster because the agent drafts and cites policy sources for them.

Baseline

Enquiries answered within SLA: 72%, ai-prd.md (made up)
Average first reply time: 3 days, ai-prd.md (made up)
Minutes per policy search: 12, ai-prd.md (made up)

Target and review date

*Proposed*

Drafts sent after light edit: ≥ 70% (7 in 10), 30 days after go-live
D4 average (usefulness): ≥ 3.5, Weekly
D5 average (tone): ≥ 3.0, Weekly
Deal-breaker pass rate: 100%, Every eval
Enquiries answered within SLA: ≥ 85%, 30 days after go-live
Average first reply time: ≤ 1 day, 30 days after go-live

Usage metric

*Proposed*

Adoption rate: % of eligible enquiries where agent draft is generated, ≥ 90% within 2 weeks
Edit rate: % of drafts edited before send, Track trend (lower is better)
Rewrite rate: % of drafts rewritten from scratch, < 30% (kill switch if exceeded)
Skip rate: % of drafts where officer ignores and writes manually, < 20%

Pattern I’ll watch for first

*Proposed*

Watch for: Officers consistently rewriting drafts for one topic or source.

Officers adding the same information every time: Source is missing common detail, Policy Team Lead updates source
Officers deleting the same phrase every time: Agent tone is off, Product Owner reviews tone guidelines

Stop line

*Proposed*

Any deal-breaker case fails: 1 failure, Product Owner, Stop and fix within 3 days
D4 average drops below threshold: < 3.5 on everyday cases, Product Owner, Review draft quality
Rewrite rate too high: > 50%, Product Owner, Stop or pivot
Officers stuck on core action: > 3 minutes average, Ops Lead, Check draft quality
Source staleness rate: > 50% sources outdated, Policy Team Lead, Pause until sources updated
Wrong information sent to resident: 1 incident, Technical Owner / Ops Lead, Incident playbook (see operating-model.md)
